# 三、阶段一：完善详细设计

编码前先重新执行一次详细设计可实施性审查，并解决至少以下问题。涉及关键业务口径时按上一节规则向用户询问；不能让开发人员在代码中自行猜测。

## 3.1 必须闭合的关键设计问题

1. 历史重放接口：使 Strategy 能按每个历史决策日取得当时可见的股票池、状态、财务快照和系统因子。明确采用带 `as_of_date` 的查询，或 `ResearchDataView.at(date)` 等等价且受限的历史视图；不得用当前 D 日证券状态重放过去。
2. 理论策略组合回撤：现有文档中的“60 日回撤窗口”和“从起点至 D 的 running maximum”并不等价。这是关键决策，先向用户确认采用滚动 60 个交易日峰值，还是从固定理论净值起始日以来的峰值；随后统一历史重放长度、状态机、公式和测试。
3. AccountSnapshot 完整性：明确区分空仓、持仓未知和持仓部分提供。定义机器可读的完整性状态，以及每种状态下允许或禁止生成的建议字段。
4. 账户管理范围：明确策略管理总资产和券商全账户总资产的区别，定义管理范围、范围完整性和范围外资产字段，禁止仅依赖自由文本说明范围。
5. 正式 Artifact Schema：为全部 JSON、CSV 和 Parquet 文件定义版本化物理 Schema，包括字段类型、必填性、空值、主键、唯一性、枚举、单位、Decimal 精度、日期/时区、排序、嵌套结构和兼容规则。至少覆盖 Manifest、Raw、Research、用户因子、Target、Backtest、Trade、Unfilled、Portfolio Daily、Metrics、Period Metrics、Trade Advice 和 Failure Diagnostic。
6. 自定义因子验收路径：定义至少一个正式可运行、可端到端验收的自定义因子使用方式。可以为批准的策略增加显式可选因子配置，或定义最小正式参考因子策略；不得只在测试内部伪造一个产品无法使用的策略。
7. Tushare 数据映射：冻结每个内部 dataset_id 对应的精确接口、请求字段、响应字段、单位、分页键、唯一键、空响应语义、权限要求、历史覆盖和后备策略，特别处理历史 ST、ETF 复权、财务修订、停复牌、涨跌停和公司行为。

## 3.2 必须消除的实现歧义

1. 所有策略算法使用解析后的配置参数，默认数字只能作为默认值，不能在算法流程中形成另一套硬编码规则。
2. 冻结百分位归一化公式、分位数插值、缩尾、OLS、年化斜率、波动率、缺失值、同分排序、浮点/Decimal 边界及权重舍入规则。
3. 为 `risk_flags`、`quality_flags`、`reason_codes`、`explanation_codes` 和 Issue 建立权威命名空间、枚举、严重性、产生模块与下游行为；消除名称不一致。
4. 明确理论基础组合在周度调仓之间是保持目标权重还是允许权重自然漂移，并使回撤公式和测试一致。
5. 明确 Backtest RebalancePlan 的估值时点和目标数量参考价格，定义 D 日目标、T 日开盘、滑点价格、交易单位、费用、卖出回款和现金约束之间的确定性顺序。
6. 明确现金分红采用税前还是税后金额、税费假设、送转股、拆并股、配股、零股、登记日、除权日和支付日的账户事件顺序。
7. 冻结年化收益的收益区间数量、Sharpe、Calmar、换手率、滑点成本、资产收益贡献和最大回撤区间等指标的精确公式。
8. 定义 Windows 上目录原子发布、显式覆盖、进程中断和失败恢复的实际算法；不能只引用 POSIX rename 语义。
9. 冻结 Python 版本范围、依赖和锁定方式、代码格式、静态检查、测试框架、覆盖率门槛、支持平台、资源默认值和 CI/本地统一验证命令。
